Paint like Pollock

Creative coding, interactive tools, interface design

An interactive webpage using p5.js and the ml5.js library that allows its users to create illustrations by tracking different parts of their face. The user can adjust the brush size by opening and closing their mouth, and moving the brush by moving their head around. The intended usage of the tool was for play and experimentation, encouraging the user to explore the ways physical motion can be translated into a digital illustration.

Question

How can we use facial movements as a form of creation and reimagine alternate ways of illustration?

Answer

Movements in the face that correspond to different brush sizes and drawing techniques.

Initial Prototypes

Experimenting with blinking

I originally experimented with how blinking can be used as a mechanism to start and stop drawing. I created a very basic prototype, but soon it was clear that it was finicky and very difficult to use.

The facial recognition software couldn’t always pick up on the user blinking, especially when their head would be moving around in different angles, and that meant the user had very little control over the software and how the final drawing would appear. I decided to experiment with using the mouth as the main controller of brush size, given that there was a larger variation in the mouth size which the computer would easily pick up on.

Layout considerations

From the first prototype, I felt that it was a little difficult to see where I was drawing on as the frame begins to be filled with brush strokes. I wanted to see if a separate canvas and camera screen would be easier to use, as it would allow the user to see themselves and the drawing clearly.

I tried different layouts for how the drawing would appear on screen, including one where the camera and drawing were side by side on the screen. From user feedback, it turned out that the original layout where the drawing was overlayed on top of the camera was the most intuitive, and that a more straightforward solution to the problem would be to include a function where the user can turn their camera on and off.
